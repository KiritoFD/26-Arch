### 3.2 静态分支预测优化

**目标：** 在 ID 阶段做分支预测，减少分支惩罚

**需要修改的内容：**

1. **core_decode.sv 修改：**
   - 添加预测输出端口（2 个信号）
   - 添加预测逻辑（30-40 行）
   - 需要访问操作数（已有）

```systemverilog
// 添加输出端口
output logic        predict_taken,
output logic [63:0] predict_target

// 添加预测逻辑
always_comb begin
    predict_taken = 1'b0;
    predict_target = 64'd0;
    
    if (id_r.valid) begin
        // JAL/JALR 总是跳转
        if (id_dec_is_jal || id_dec_is_jalr) begin
            predict_taken = 1'b1;
            predict_target = ...;
        end
        // 条件分支：后向预测跳转
        else if (id_dec_is_branch) begin
            if (id_dec_imm[63]) 
                predict_taken = 1'b1;
            predict_target = id_r.pc + id_dec_imm;
        end
    end
end
```

2. **core_execute.sv 修改：**
   - 添加预测输入端口（2 个信号）
   - 添加预测错误检测输出（1 个信号）
   - 添加预测验证逻辑（10-15 行）

```systemverilog
// 添加输入端口
input  logic          predict_taken,
input  logic [63:0]   predict_target,

// 添加输出端口
output logic          predict_error

// 预测错误检测
assign predict_error = ex_r.valid && 
                       (ex_r.is_branch || ex_r.is_jal || ex_r.is_jalr) &&
                       ((predict_taken != ex_branch_taken) || ...);
```

3. **core.sv 修改：**
   - 添加预测信号声明（3 个信号）
   - 修改 core_decode 实例化
   - 修改 core_execute 实例化
   - 修改分支跳转逻辑（20-30 行）
   - 修改取指逻辑（配合预测）

```systemverilog
// 信号声明
logic        predict_taken;
logic [63:0] predict_target;
logic        predict_error;

// 修改跳转逻辑
assign ex_flush_front = ... || predict_error;
assign ex_redirect_pc = predict_error ? ex_next_pc : predict_target;
```

**工作量估算：**
- 代码修改：80-100 行
- 测试验证：3-4 小时（需要验证预测错误恢复）
- 调试修复：2-3 小时
- **总计：6-8 小时**

**风险评估：**
- 中等风险：需要验证预测错误恢复逻辑
- 需要测试各种分支场景
- 需要验证异常和中断处理

## 四、未实施的技术原因

### 4.1 时间限制

**指令预取缓冲：**
- 需要 4-6 小时完整实施
- 需要修改 150-200 行代码
- 需要仔细测试边界情况

**静态分支预测：**
- 需要 6-8 小时完整实施
- 需要修改 80-100 行代码
- 需要验证预测错误恢复

**总计：10-14 小时**

### 4.2 复杂度分析

**指令预取缓冲：**
- 涉及多处关键逻辑修改
- 需要维护 FIFO 队列状态
- 需要处理分支跳转时的缓冲冲刷
- 需要协调 IF/MEM 总线冲突

**静态分支预测：**
- 需要修改流水线控制逻辑
- 需要添加预测错误恢复机制
- 需要验证预测正确性
- 需要测试各种分支场景

### 4.3 风险控制

**当前优化（MEM 前递）：**
- 低风险：只修改前递逻辑
- 易验证：所有测试通过
- 效果明显：+8.5% IPC

**未实施优化：**
- 中等风险：涉及流水线控制
- 需要大量测试验证
- 可能引入难以发现的 bug
